# The Claude Agent SDK: credentials, providers and terms

## Summary

the Agent SDK runs the Claude Code binary, so it supports the same credentials: Anthropic API key, bearer token for a gateway, `apiKeyHelper`, a long-lived subscription token from `claude setup-token`, Bedrock, Claude Platform on AWS, Vertex (Google Cloud's Agent Platform) and Microsoft Foundry. One process uses one credential, picked by a fixed precedence. A program can run separate `query()` sessions with different `env`, so it can use a different provider per session, but **not per subagent**: subagents share their session's provider. You **can** set a different model per subagent. Anthropic **doesn't support non-Claude models** through a gateway. The SDK docs say third-party developers may not offer claude.ai login, and the legal page says Agent SDK developers "should use API key authentication". In practice, a subscription login is for the person's own ordinary use, and anything that ships to other users needs an API key or a cloud provider.

## The SDK (inventory section 4)

- **Does.** A Python or TypeScript library that runs the Claude Code binary as a subprocess. It has the same tools, hooks, subagents, permissions, sessions, skills and plugins [doc, [agent-sdk/overview](https://code.claude.com/docs/en/agent-sdk/overview)]. Agents can be defined in code (`agents:` with `AgentDefinition`, which has the same `skills` and `model` fields) and take precedence over file agents with the same name [doc, [agent-sdk/subagents](https://code.claude.com/docs/en/agent-sdk/subagents)]. The orchestrating program sees structured task events, can stop tasks, interrupt and resume, and can mirror transcripts to its own storage [doc, [agent-sdk/typescript](https://code.claude.com/docs/en/agent-sdk/typescript), [agent-sdk/session-storage](https://code.claude.com/docs/en/agent-sdk/session-storage)]. `settingSources: []` isolates it from the user's `~/.claude` [doc, [agent-sdk/claude-code-features](https://code.claude.com/docs/en/agent-sdk/claude-code-features)], which bears on discovery 0004's stale-skill problem.
- **Auth, providers and models.**
  - **Credentials.** Precedence: cloud provider (`CLAUDE_CODE_USE_BEDROCK`, `_VERTEX`, `_FOUNDRY`; Claude Platform on AWS via `CLAUDE_CODE_USE_ANTHROPIC_AWS`) > `ANTHROPIC_AUTH_TOKEN` (gateway bearer) > `ANTHROPIC_API_KEY` > `apiKeyHelper` > `CLAUDE_CODE_OAUTH_TOKEN` (one-year subscription token from `claude setup-token`) > Anthropic profile > `/login` subscription [doc, [authentication#authentication-precedence](https://code.claude.com/docs/en/authentication#authentication-precedence)]. These apply to the SDK too [doc, same page; [agent-sdk/quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)].
  - **Switching.** One process uses one credential. The SDK's `env` option is set per `query()`, so one program can run sessions on different providers [doc for `env`, [agent-sdk/configuration](https://code.claude.com/docs/en/agent-sdk/configuration); inferred for mixing]. `AgentDefinition` has no provider or `env` field, so **every subagent uses its session's provider** [doc, field table; inferred conclusion].
  - **Model per subagent.** Yes, through `model` [doc]. The model ID must be valid on the session's provider [inferred].
  - **Non-Anthropic models.** "Anthropic … doesn't support routing Claude Code to non-Claude models through any gateway" [doc, [llm-gateway](https://code.claude.com/docs/en/llm-gateway)]. `ANTHROPIC_BASE_URL` changes where requests go, not which model answers [doc, [model-config](https://code.claude.com/docs/en/model-config)]. A gateway that translates to another vendor's model might technically work, but it's unsupported [inferred]. The docs also say: "In every approach the workers are Claude sessions. To involve a different tool, expose it to Claude as an MCP server" [doc, [agents](https://code.claude.com/docs/en/agents)].
  - **Terms.** "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK" [doc, [agent-sdk/overview](https://code.claude.com/docs/en/agent-sdk/overview)]. OAuth is "intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans … ordinary use of Claude Code and other native Anthropic applications". Developers "including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider". "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK" [doc, [legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance)]. SDK use is governed by the Commercial Terms [doc, overview]. Reading: a myelin harness built on the SDK and used by other people should expect each user to bring an API key or a cloud credential. Using a personal subscription through the SDK is at best a grey area for anything beyond one person's own ordinary use [inferred].
- **Can't.** It can't be used without credentials and spend; it wasn't run for this inventory. It doesn't remove the dependency on the Claude Code binary [doc].
- **Answers.** myelin would need its own harness (the SDK) when orchestration must be code-driven and run outside an interactive session: unattended loops, CI, a structured event stream for an observer, or a container per worker. For orchestration inside an interactive session (the interlocutor), the CLI primitives above are enough [inferred].
- **Neutral interface vs adapter.** The SDK *is* a second Claude Code adapter (a programmatic one) behind the same spawn, observe, message and stop interface as section 2.
